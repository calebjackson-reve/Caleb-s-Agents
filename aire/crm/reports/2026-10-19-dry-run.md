# CRM engine dry run against the real AIRE CRM, 2026-10-19

Run in the cloud session with `--local` on a read-only snapshot of the live sheet (all 3,626 Contacts rows plus the Notes and Connector Log rows pulled through the Google Sheets connector at about 4:40 pm Central). No Google token exists in the cloud, so no write to the sheet was possible, and the snapshot's SHA-256 was identical before and after every command (`dd401407c9d5fd1a…`).

## Blueprint

1. `check` reads the live header and compares it to the 25 columns the engine expects.
2. `feed --as-of 2026-10-19` computes touches due by band cadence, open tasks, live deals and new leads, and writes feed.json.
3. `--dry-run ingest` parses the real last 7 days of Luxury Presence, ShowingTime and Authentisign mail (66 messages, read through the Gmail connector, bodies limited to the snippet) and lists every write it would make.
4. `--dry-run merge-hwc` classifies the 458 Hot-Warm-Cold rows against the CRM. Separate report: `2026-10-19-hwc-merge-dry-run.md`.
5. On a scratch copy only, the merge was applied, the mail ingested and tasks synced, then `feed` run again, to show what the Pipeline app would get after Caleb's yes.

## Unknowns

- Cadence for NURTURE (90 days) and DORMANT (365) is inferred from the band names. Caleb has not set those numbers.
- Whether the 117 HOT band rows from the August scoring should stay HOT, or whether band should be reset to Caleb's hand tiers. The merge plan never changes a band that is already set, so this stays as it is until he decides.
- Mail bodies in this dry run were snippets, not full text. Phone numbers inside Luxury Presence lead mail were therefore not parsed; the Mac run reads full bodies.
- The Mac's `crm_client` source was not readable from the cloud. The gates here are implemented from Caleb's description of them (person_id only, Do_Not_Contact one way, never Command_ID, every write audited). If `crm_client` has a rule beyond those four, it is not here yet.
